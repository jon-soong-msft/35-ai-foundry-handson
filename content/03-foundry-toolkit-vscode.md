The **Foundry Toolkit for VS Code** brings Microsoft Foundry directly into the editor — browse deployed models, open a live playground, create agents, inspect tool catalogs, and generate production-ready code without switching to the browser.

> [!NOTE]
> This workshop is **portal-first** — every hands-on task is done inside the Foundry portal at [ai.azure.com](https://ai.azure.com). This module is included as a **read-only concept** so you know the editor-based option exists. It is entirely optional; you can complete the whole workshop without it.

## What the toolkit gives you

- **My Resources** — see the models deployed in your project, straight from the Activity Bar.
- **Developer Tools** — browse the **Model Catalog** and **Tool Catalog**, and open the **Model Playground** to test prompts inside VS Code.
- **Agent Builder** — create and iterate on Prompt Agents in the editor (the same kind of agent you build in the portal in [Module 04](04-prompt-based-agents.html)).
- **Code generation** — generate starter client code for any deployed model so you can move from playground to application quickly.

## Why it matters

The toolkit is the developer-centric companion to the portal. Teams that live in VS Code can design, test, and wire up agents without context-switching, then generate the code to call them from an app. If your clients have developers who prefer the editor, this is where they'd start — but the concepts (models, playground, tools, agents) are identical to what you do in the portal.

## When you'd use it instead of the portal

| Prefer the portal when… | Prefer the toolkit when… |
|---|---|
| You want a guided, click-through experience | You already work in VS Code all day |
| You're demoing or teaching | You want to generate and edit client code |
| You have no local dev environment | You're building an app around the agent |
